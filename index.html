WMS-WitLegacy

A mock legacy warehouse host — no API, no JSON, no events. Files and batches: fixed-width records dropped in an IN/ folder, results staged one batch and released the next, extracts on a schedule, and an 80×24 character terminal for the operators. Python standard library only. It runs the same canonical warehouse as the modern host, value for value.

The twelve acts

CodeMeaning
RCPTRECEIVE TO DOCK
PUTAPUTAWAY DOCK TO BIN
ADJTINVENTORY ADJUST
RLSERELEASE ORDER
PICKPICK TO ORDER
SHRTSHORT AN ORDER LINE
PACKPACK ORDER (MAKES DELIVERY)
LOADPUT DELIVERY ON LOAD
SHIPSHIP LOAD
CNTSCOUNT SUBMIT
EXCPLOG EXCEPTION
LABRLABOR START/END

Short work is a first-class citizen here too: SHRT shorts an order line and raises the SP “SHORT PICK/SHIPMENT” exception flag — one flag from the floor, one from the shipment, because the shipment's record is what a delivery is read against. Bad records don't stop the batch: they come back in the reject file with a code (for example R01 — bad record (length, type, or host could not process it)) and the rest of the file still processes.

Run it yourself

git clone https://github.com/Grateful-Ed/WMS-WitLegacy.git
cd WMS-WitLegacy
python3 -m legacy_wms HOSTDIR tui      # the terminal
python3 -m legacy_wms HOSTDIR batch    # run a batch
